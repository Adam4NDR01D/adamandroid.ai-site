Sidebot-2 · Explore the Process

The full pricing-correction chain, end to end, step by step. Each step shows what we do, what it returns, and how it hands to the next link, with honest status and where each file gets created. Built like the Sidebot-1 interop fix-list. Verified live in Four51 admin, read-only, 2026-10-14 and 2026-10-15, against Jesse's SOAP handoff 2026-10-13, the Sept 29 and Oct 2 calls, and Brandi and Jesse emails, Sep 28 to Oct 13.

The goal: keep Four51 storefront prices correct for every item, size, and buyer, with far less manual updating, and catch wrong prices before a customer sees them.

Assumptions

  • Base price comes clean from the Price Breaks report per catalog. Verified, one catalog.
  • The Variable Spec report flags every product that has a SIZE spec. Report confirmed, not yet run at scale.
  • Markups are browser-readable and fixed amount per unit. Verified for Uncle Bears apparel only.
  • Editing one product's markup affects only that product. Verified on a three-product sample.
  • Markups get written to their own file before the join, so the read is auditable.
  • Source-of-truth pricing can be pulled from Quantum now and Infoplus later. Stated by Brandi, not yet obtained.
  • Effective price = base + markup for per-unit items. The three forks, lot timing, retail harmonization, tiers, are human calls, not auto-fixes.
  • The write path is Jesse's API or browser automation, not SOAP. Which one, and whether Jesse's works, is unconfirmed.
  • The Creator build goes to G from our build list, within Creator's per-call limits, unless we offer to build it.
  • We pull per catalog, because the all-catalogs export fails.
  • Day-one excludes: point-of-sale and no-online-price buyers.

Questions to troubleshoot

  • Source of truth: where do we pull today's Quantum pricing, in what format, and is it a whole per-size price or base plus modifier?
  • Jesse's write method: what API, does it set base and markup per buyer, did it work on the SSTEST items, and can it roll back?
  • Write path choice: if the API is not reliable, do we use browser automation to write through the admin screen?
  • Per-buyer pricing: can one 451 item hold per-buyer pricing, or do we need the duplicate or hyphenated-ID approach?
  • Variable Spec coverage: does every sized product use a SIZE selection spec, or are some sized differently and would get missed?
  • Markup type variance: are any products percentage or per-line instead of per-unit? We only checked one catalog.
  • Quantity breaks: some schedules have more than one break. Which break is the price for reconciliation?
  • Multiple schedules per product (B2B vs Employee): which schedule do we reconcile per buyer?
  • Buyer exclusions: the exact list of day-one excluded buyers.
  • Scale: total catalogs and sized products, so we know if scraping all markups fits in one run.
  • Creator ownership: does G want to own the build, or do we offer it, and what are the per-call limits for a scheduled run?
